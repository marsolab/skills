# Go Database Access (sqlc + goose)

Write SQL, generate Go. sqlc reads your queries and produces typesafe
Go bindings; goose runs your migrations forward and back.

For long-form rationale, read `references/databases.md`.

## The workflow

1. Write migrations as goose-flavored SQL.
2. Write queries as plain SQL with sqlc annotations.
3. Run `sqlc generate` to produce typesafe Go.
4. Inject the generated `Queries` struct into your service layer.

## Project layout

```text
myservice/
├── db/
│   ├── migrations/      # goose migrations: 001_xxx.sql, 002_xxx.sql
│   └── queries/         # sqlc query files: users.sql, orders.sql
├── internal/db/         # generated by sqlc — do not edit
├── sqlc.yaml
└── ...
```

## sqlc.yaml configuration

```yaml
version: "2"
sql:
  - schema: "db/migrations"
    queries: "db/queries"
    engine: "postgresql"
    gen:
      go:
        package: "db"
        out: "internal/db"
        emit_json_tags: true
        emit_interface: true       # for testing
        emit_prepared_queries: false
        emit_pointers_for_null_types: true
        sql_package: "pgx/v5"
```

Key options:

- `emit_interface: true` — generates a `Querier` interface that lets
  you mock the data layer in unit tests.
- `emit_pointers_for_null_types: true` — `*string` for nullable
  columns instead of `sql.NullString`. Cleaner code.
- `sql_package: "pgx/v5"` — use pgx if you can; it's the better
  PostgreSQL driver. `database/sql` with `lib/pq` is fine too.

## Migrations with goose

Migrations are timestamped or numbered SQL files with `+goose` magic
comments:

```sql
-- db/migrations/001_create_users.sql
-- +goose Up
CREATE TABLE users (
    id    BIGSERIAL PRIMARY KEY,
    email TEXT NOT NULL UNIQUE,
    name  TEXT NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX users_email_idx ON users (email);

-- +goose Down
DROP TABLE users;
```

Run them:

```bash
goose -dir db/migrations postgres "$DATABASE_URL" up
goose -dir db/migrations postgres "$DATABASE_URL" down
goose -dir db/migrations postgres "$DATABASE_URL" status
```

For multi-statement migrations or stored procedures, use
`+goose StatementBegin`/`+goose StatementEnd`:

```sql
-- +goose Up
-- +goose StatementBegin
CREATE FUNCTION increment(i integer) RETURNS integer AS $$
BEGIN
    RETURN i + 1;
END;
$$ LANGUAGE plpgsql;
-- +goose StatementEnd
```

## Queries with sqlc annotations

Each query gets a name and a result type via a comment annotation:

```sql
-- db/queries/users.sql

-- name: GetUser :one
SELECT id, email, name, created_at
FROM users
WHERE id = $1;

-- name: ListUsers :many
SELECT id, email, name, created_at
FROM users
ORDER BY created_at DESC;

-- name: CreateUser :one
INSERT INTO users (email, name)
VALUES ($1, $2)
RETURNING id, email, name, created_at;

-- name: UpdateUserName :exec
UPDATE users SET name = $2 WHERE id = $1;

-- name: DeleteUser :execrows
DELETE FROM users WHERE id = $1;
```

| Annotation | Result |
|------------|--------|
| `:one`     | Returns a single row. Errors if zero or multiple rows. |
| `:many`    | Returns a slice of rows. |
| `:exec`    | Returns only `error`. |
| `:execrows`| Returns `(int64, error)` — number of affected rows. |
| `:execlastid`| Returns `(int64, error)` — last insert ID (MySQL only). |

After saving the SQL file:

```bash
sqlc generate
```

This regenerates `internal/db/` with the typesafe Go.

## Using the generated code

```go
import "myservice/internal/db"

type UserService struct {
    queries *db.Queries
    pool    *pgxpool.Pool
}

func NewUserService(pool *pgxpool.Pool) *UserService {
    return &UserService{
        queries: db.New(pool),
        pool:    pool,
    }
}

func (s *UserService) Get(ctx context.Context, id int64) (db.User, error) {
    user, err := s.queries.GetUser(ctx, id)
    if err != nil {
        if errors.Is(err, pgx.ErrNoRows) {
            return db.User{}, ErrNotFound
        }
        return db.User{}, fmt.Errorf("get user %d: %w", id, err)
    }
    return user, nil
}
```

## Transactions

`db.Queries` exposes a `WithTx` method (when `emit_methods_with_db_argument: false`,
which is the default) that returns a new `*Queries` bound to the
transaction:

```go
func (s *UserService) TransferCredits(ctx context.Context, from, to int64, amount int64) error {
    tx, err := s.pool.Begin(ctx)
    if err != nil {
        return fmt.Errorf("begin: %w", err)
    }
    defer tx.Rollback(ctx)

    qtx := s.queries.WithTx(tx)
    if err := qtx.DebitUser(ctx, db.DebitUserParams{ID: from, Amount: amount}); err != nil {
        return fmt.Errorf("debit: %w", err)
    }
    if err := qtx.CreditUser(ctx, db.CreditUserParams{ID: to, Amount: amount}); err != nil {
        return fmt.Errorf("credit: %w", err)
    }
    if err := tx.Commit(ctx); err != nil {
        return fmt.Errorf("commit: %w", err)
    }
    return nil
}
```

The deferred `Rollback` after a successful `Commit` is a no-op
(transaction is closed) — safe to keep as a guard against early
returns.

## Testing

### Unit tests with the Querier interface

`emit_interface: true` produces a `Querier` interface matching every
generated method. Mock it for unit tests of your service layer:

```go
type mockQueries struct {
    db.Querier
    getUser func(context.Context, int64) (db.User, error)
}

func (m *mockQueries) GetUser(ctx context.Context, id int64) (db.User, error) {
    return m.getUser(ctx, id)
}

func TestUserService_Get(t *testing.T) {
    svc := &UserService{queries: &mockQueries{
        getUser: func(_ context.Context, id int64) (db.User, error) {
            return db.User{ID: id, Email: "a@example.com"}, nil
        },
    }}
    // ...
}
```

For most cases, embedding `db.Querier` and overriding only the methods
you care about is cleanest.

### Integration tests with a real database

Mocks miss query bugs that only surface against a real DB. Gate
integration tests on an env var, run them in CI against a throwaway
Postgres:

```go
func TestUserService_Integration(t *testing.T) {
    dsn := os.Getenv("TEST_DATABASE_URL")
    if dsn == "" {
        t.Skip("set TEST_DATABASE_URL to run integration tests")
    }
    ctx := context.Background()
    pool, err := pgxpool.New(ctx, dsn)
    if err != nil {
        t.Fatalf("connect: %v", err)
    }
    t.Cleanup(func() { pool.Close() })

    // Run migrations against the test DB.
    if err := goose.Up(stdlib.OpenDBFromPool(pool), "db/migrations"); err != nil {
        t.Fatalf("migrate: %v", err)
    }

    svc := NewUserService(pool)
    // ... real queries, real assertions
}
```

CI workflow: spin up a Postgres container, set `TEST_DATABASE_URL`,
run `go test -race ./...`. The build tag–free env-var gate makes
skipped tests visible (`t.Skip` shows in `-v` output).

## Raw database/sql when you need it

Some patterns don't fit query files cleanly: dynamic IN clauses with
variable arity, full-text search with arbitrary user input, ad-hoc
admin queries. For those, drop down to `database/sql` (or pgx
equivalents):

```go
rows, err := db.QueryContext(ctx, "SELECT id, email FROM users WHERE id = ANY($1)", ids)
if err != nil {
    return nil, fmt.Errorf("query users: %w", err)
}
defer rows.Close()

var out []User
for rows.Next() {
    var u User
    if err := rows.Scan(&u.ID, &u.Email); err != nil {
        return nil, fmt.Errorf("scan: %w", err)
    }
    out = append(out, u)
}
if err := rows.Err(); err != nil {
    return nil, fmt.Errorf("iterate: %w", err)
}
return out, nil
```

Always check `rows.Err()` after the loop — `rows.Next()` returning
`false` doesn't distinguish "done" from "errored mid-stream".

## Quick reference

- `sqlc.yaml` with `emit_interface: true` and `emit_pointers_for_null_types: true`.
- Migrations: `db/migrations/NNN_name.sql` with `-- +goose Up`/`Down`.
- Queries: `db/queries/*.sql` with `-- name: X :one|:many|:exec|:execrows`.
- Use `WithTx` for transactions; defer `Rollback` even after `Commit`.
- Unit-test with mocks of `db.Querier`; integration-test with a real
  DB gated on `TEST_DATABASE_URL`.
- Drop to `database/sql` for dynamic queries that don't fit sqlc.
